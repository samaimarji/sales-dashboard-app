# Dealer Dashboard: notes for Claude

## Owner
- The owner is a Cricket district manager, not a developer. Explain in plain language, 1–2 sentences at a time.
- Work in small, clickable steps. After each step, say how to open it and what to check.
- Ask before spending money, creating accounts or deploying. The owner creates all accounts and types all passwords.

## Hard rules
- **Never put real rep names, real store data or customer data in this repo.** Sample data is generated by
  `scripts/seed-demo.ts` from generic name lists.
- Never write to the owner's "Velocity Sales Dashboard 2.0" Google Sheet (read only).
- Anyone flagged `hidden_from_rep_views` must never appear by name in rep lists, rankings or cards, but their
  numbers always count in totals.
- Never average percentages across stores or reps. Use the KPI's `agg` rule in `src/lib/kpis/catalog.ts`.

## Architecture
- Next.js (App Router, TypeScript, Tailwind) + Postgres via the `postgres` npm package.
- Dealer data access goes through `withDealer()` in `src/lib/db.ts` (role `dd_app`, row-level security).
  `adminSql` is only for migrations, seed, login lookups and platform-admin pages.
- Screens read `org_rollup_daily` (pre-added totals). Never load all stores or reps into the browser.
  Always page and filter on the server.
- New schema changes go in a new `db/migrations/NNN_name.sql`. Don't edit migrations that have shipped.
- Power BI files are identified by header row, never by file name. Column mapping lives in the KPI catalog `sources`.

## Commands
- `npm run db:reset`: wipe the local DB, migrate and seed (~5 min)
- `npm run db:migrate`, `npm run db:seed`, `npm run dev`, `npm run build`, `npm run lint`

## Roadmap
v1: (1) setup + DB + sample data ✅ (2) daily upload with reconciliation (3) screens (4) hide/merge settings
(5) logins and roles (6) speed test at 1,000 stores.
Later: schedule planner (labor budget and lunch rules), commission calculator, email/Drive imports, billing per store.
