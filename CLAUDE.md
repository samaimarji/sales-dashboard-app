# Dealer Dashboard: notes for Claude

## Owner
- The owner is a Cricket district manager, not a developer. Explain in plain language, 1–2 sentences at a time.
- Work in small, clickable steps. After each step, say how to open it and what to check.
- Ask before spending money, creating accounts or deploying. The owner creates all accounts and types all passwords.

## Hard rules
- **Never put real rep names, real store data or customer data in this repo.** Sample data is generated by
  `scripts/seed-demo.ts` from generic name lists.
- Never write to the owner's "Velocity Sales Dashboard 2.0" Google Sheet (read only).
- Anyone flagged `hidden_from_rep_views` must never appear by name in rep lists, rankings or cards, but their
  numbers always count in totals.
- Never average percentages across stores or reps. Use the KPI's `agg` rule in `src/lib/kpis/catalog.ts`.

## Architecture
- Next.js (App Router, TypeScript, Tailwind) + Postgres via the `postgres` npm package.
- Dealer data access goes through `withDealer()` in `src/lib/db.ts` (role `dd_app`, row-level security).
  `adminSql` is only for migrations, seed, login lookups and platform-admin pages.
- Screens read `org_rollup_daily` (pre-added totals). Never load all stores or reps into the browser.
  Always page and filter on the server.
- New schema changes go in a new `db/migrations/NNN_name.sql`. Don't edit migrations that have shipped.
- Power BI files are identified by header row, never by file name. Column mapping lives in the KPI catalog `sources`.

## Commands
- `npm run db:reset`: wipe the local DB, migrate and seed (~5 min)
- `npm run db:migrate`, `npm run db:seed`, `npm run dev`, `npm run build`, `npm run lint`
- `npm run samples -- --dealer sunrise --date 2026-10-30 [--break]`: write fake Power BI exports to `samples/`
- `npm test`: importer tests (generate the sunrise and broken pacific-coast samples first)

## Daily import (step 2)
- Flow: upload API stores files (`src/lib/storage.ts`) → pg-boss job `import-check` (read, recognize, reconcile)
  → if no errors, save; otherwise status `needs_review` until "Save anyway" (`import-save` job) or "Cancel".
- Code: `src/lib/imports/` (`parse.ts` reads/recognizes, `reconcile.ts` checks, `merge.ts` combines files, `save.ts` writes).
- MTD "Activations" = Total Connected Gross Adds (wireless + Home Internet), verified against real files.
  `wireless_gross_adds` is the wireless-only number.
- Saving a date deletes and rewrites that date (no duplicates), then refreshes rollups for that date.
- Mismatched stores are **held**, not the whole day (owner's choice): held stores keep their last good snapshot
  from the same month (`import_held_stores.carried_from`) until "Save anyway". File-level problems, or more than
  max(5, 20%) of stores failing, hold the whole day (`needs_review`). Issue report: `/api/d/<slug>/imports/<id>/report` (CSV).
- Employee IDs match case-insensitively. Unknown stores are added under the company level (`auto_added`).

## Screens (step 3)
- Overview `/d/<slug>?unit=` (any level above store), store card `/store/<id>`, rep card `/rep/<personId>`,
  KPI report `/report` (checklist builder, saved reports), rankings `/rankings`, opportunities `/opportunities`.
- Pace (`src/lib/kpis/pace.ts`): volume KPIs vs goal × share of month; rates vs target. Colors: blue 150%+, green on pace,
  orange 70%+, red behind (same as the owner's sheet).
- Goals (`src/lib/kpis/goals.ts`): count goals = store goals added up; rate targets = nearest ancestor's. Rep goals =
  store goal split evenly among people selling there.
- Rep lists always go through `repsUnder()` (`src/lib/reps.ts`), which excludes hidden people and combines multi-store reps.
